4. Cái bẫy đã biết (đọc trước khi sửa)

  1. Chỉ số trong asset là thang GDD thô. Ví dụ Attack = 100 nghĩa là “1.00 lần”; code chia 100 khi dùng — xem TankBrain.cs:1199 (/ 100f). Đừng “sửa lỗi” thành 5.
  2. StageManager.cs là xác cũ. Không scene nào còn gắn nó; màn chơi dùng StageDirector. Đọc nhầm file này sẽ hiểu sai luồng.
  3. SaveSystem không nằm trong scene nào. Nó tự khởi tạo bằng [RuntimeInitializeOnLoadMethod(BeforeSceneLoad)]; muốn biết file đang ghi ở đâu thì log SaveSystem.Instance.SaveFilePath.
  4. Không có asmdef. Sửa một file là Unity biên dịch lại toàn bộ 226 file — đừng ngạc nhiên khi chờ lâu.
  5. Tài liệu trong docs/ đã lệch code. Ví dụ tài liệu cũ ghi “chỉ SampleScene trong build”, nay có 16 scene; vài chỗ còn mô tả schema TankDefinition cũ. Tin code trước, tin docs sau.
  6. Mỗi scene màn phải tự gắn StageDirector. Nó là component đặt trong scene, không phải tự sinh — quên gắn thì màn trống, không có quái và không có điều kiện thắng.

5. Bốn luật không được vi phạm

  1. Không đặt SpriteRenderer / Animator / AudioSource / ParticleSystem trong Brain.
  2. Mọi Collider sinh ra trong trận phải có ColliderOwnerRef.
  3. Đạn, tia, nổ, chữ sát thương: lấy từ pool, không Instantiate/Destroy trong lúc đánh.
  4. Chỉ số runtime phải có [ReadOnly].
